Words mean different things in different company. "Bank" by a river is not "bank" on a statement. In "The server rejected the request because it was malformed", you instantly know "it" means the request, not the server. A model has to work that out too, and the mechanism it uses is called <Term k="attention">attention</Term>.

After the previous chapter, each word is a point on the map of meaning (strictly, each token, but "word" is easier to picture), but each one only knows about itself. Attention lets every word look back at the words before it, decide which ones matter for its own meaning, and blend in information from them.

<Note title="Like a good meeting">
Picture a meeting where each person, before speaking, can only listen back to those who have already spoken, and pays most attention to the ones whose points matter for what they're about to say. Everyone does this at once, and many times over.
</Note>

Notice the dashed words: a word can only look *backwards*. The model is trained never to look ahead, even in text it has already been given, because when it writes, the future doesn't exist yet.

## Why this was the breakthrough

Older language models read text strictly word by word and had to squeeze everything they'd read into a small running summary, so they forgot the beginning of long sentences. Attention lets every word reach back to *any* earlier word directly. Attention itself appeared in 2014, as an add-on to those older models. The 2017 paper that introduced the <Term k="transformer">transformer</Term>, the design behind almost every chatbot today, threw away the word-by-word reading entirely and kept only attention.

This has a price that comes back in later chapters: every word compares itself with every earlier word. Double the length of the text and the *attention* part of the work roughly quadruples. For everyday prompt lengths the total grows closer to double, but for very long texts the quadratic part dominates.

## Why this matters to you

- **Context steers the answer.** Each word takes its meaning from what came before it, so the same question gets a different answer when different material sits in front of it.
- **Extra text isn't neutral.** A stray paragraph in a pasted document can colour the reply, because every later word can draw on it. Give the model what it needs and leave the rest out.
- **Be specific where it counts.** If a pronoun or a name could point to several things, say which one you mean.

<Note title="Security lens" kind="warn">
Attention lets every token draw on every earlier token, whoever wrote it. Your instructions, the system prompt and a web page the model just read all sit in the same sequence, and nothing in the mechanism marks some of them as commands and the rest as data. That missing wall is why [prompt injection](/learn/prompt-injection/) works, and why Part 3 treats it as a design problem rather than a bug to patch.
</Note>

<Engineer title="Query, key, value: attention as a soft lookup">
Attention works like a lookup in a hash table, except that every entry matches a little and the results are blended.

Each token produces three vectors from its own row by multiplying it with three learned weight matrices (<Term k="qkv">query, key, value</Term>). The query says what this token is looking for. The key says what it offers to others. The value is what it hands over when it is chosen.

To update one token, the model compares its query with the key of every earlier token. The comparison is a dot product: multiply the two vectors number by number and add up the results, so a large score means a good match. The scores are divided by the square root of the vector length to keep them in a workable range, and softmax turns them into weights that add up to 1. The token's update is the weighted sum of the values. Pick a query and follow the numbers:

<Qkv />

Future tokens are excluded by the <Term k="causal">causal mask</Term>, which sets their scores to minus infinity before softmax, so their weight is exactly zero. Switch the query to "rejected" to see it.

**Many lookups at once.** One such lookup is an <Term k="head">attention head</Term>. Real models run dozens per layer side by side, each with its own small weight matrices, so different heads can track different relations: one the grammar, another which noun a pronoun refers to. Keys and values take memory, so most models use <Term k="gqa">GQA</Term>, where several query heads share one set of keys and values. Llama 3 70B has 64 query heads but only 8 key/value heads.

**Where position comes from.** A dot product ignores order: shuffle the tokens and every score stays the same. So position has to be added. Most current models use <Term k="rope">RoPE</Term>, which rotates each query and key by an angle that depends on its position, so the score between two tokens depends on how far apart they are. Extending a context window means stretching those rotations and then training briefly on long documents.

**Induction heads.** Anthropic researchers found a pair of heads that work together to continue patterns: find where the current token appeared before, and predict what followed it last time. These <Term k="induction">induction heads</Term> appear suddenly during training and explain much of how models copy from their context. In larger models, other heads seem to do more of the work of inferring a task from examples. For coding, this copying is why models follow patterns already in the context so well: an existing test, a naming convention, a neighbouring handler.

**Attention sinks and gates.** Many heads park their attention on the first token when nothing else is relevant, which is called an attention sink ([Xiao et al., 2023](https://arxiv.org/abs/2309.17453)). Adding a gate after the attention output removes most sinks and helps with long contexts ([Qiu et al., 2025](https://arxiv.org/abs/2505.06708), a NeurIPS 2025 best paper). Qwen3.5's attention layers use such a gate.

**What it costs.** Reading a prompt of n tokens takes about n²/2 query-key scores per head per layer, all computed in parallel. Each new token afterwards costs work proportional to n, against the cached keys. So a huge prompt is affordable, but a long conversation gets gradually slower. FlashAttention computes exactly the same result without ever writing the full table of scores to memory, which is what made long contexts practical ([Dao et al., 2022](https://arxiv.org/abs/2205.14135)). For a 70B-class model, attention only overtakes the rest of a token's work once that token looks back over about 50,000 earlier tokens.
</Engineer>
