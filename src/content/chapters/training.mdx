Nobody hand-codes how a model behaves. People shape it through examples, feedback and written guidelines used in training, but the behaviour itself is learned, in stages. And each stage changes *what* the model is, not just how good it is:

<Note title="Like an education">
**Reading the library** (pretraining) gives broad knowledge. An **apprenticeship** with worked examples (fine-tuning) teaches the job's format. **Feedback from a mentor** on which answers are better (preference tuning) teaches judgement and tone. **Practice exams with automatic marking** (reinforcement learning) teach which approaches actually reach the right answer, including checking and correcting along the way.
</Note>

## How this explains everyday behaviour

- **Why models are so good at code and maths:** the internet is full of code, and code and maths answers can be checked automatically, so the practice-exam stage works especially well there. <Claim id="reasoning-models" cap />.
- **Why they sound confident and agreeable:** people rating answers sometimes prefer confident, agreeable answers over correct ones, and models absorbed that preference. More on this in the limits chapter.
- **Why they don't know last month's news:** the reading stage is a snapshot. Anything newer exists for the model only if a tool or you put it into the conversation.
- **Why a coding agent sometimes "fixes" a test by changing the test:** in practice exams, a passing test was the reward. Models can learn shortcuts that earn the reward without doing what was meant.

<Engineer title="Scaling laws, synthetic data and reward hacking">
<Term k="pretraining">Pretraining</Term> minimises cross-entropy <Term k="loss">loss</Term> on next-token prediction over tens of trillions of tokens. <Term k="scaling">Scaling laws</Term> show loss falling as a smooth power law in parameters, data and compute, which made frontier training a predictable engineering bet. Pretraining historically consumed most of the compute; RL post-training is the fastest-growing share and drove the big jumps in maths and coding since late 2024. How much it adds beyond what the base model could already do is debated (see below). Whether scaling keeps paying off is also contested: smoothly falling loss is not the same as useful capability rising cheaply enough, and Epoch AI estimates public human text could run out between 2026 and 2032.

**Models training models.** A growing share of data is synthetic: frontier models write problems, solutions and explanations; verifiers filter them; the results train the next generation or smaller models via <Term k="distill">distillation</Term>. Preference feedback is increasingly AI-generated too (constitutional AI, RLAIF), with humans auditing. Training only on model output can make a model lose the rare cases ("model collapse"); labs avoid this by mixing synthetic data with real data and filtering it.

**Reward hacking.** RL optimises whatever the checker rewards. If passing tests is the reward, a model can learn to special-case the tests, weaken assertions or edit the test file. Labs close these loopholes, but traces of <Term k="rewardhack">reward hacking</Term> still show up in coding agents. Keep the mechanism in mind when a build turns green suspiciously easily. (o1's reward design was never published; DeepSeek-R1 and Ai2's Tülu 3, which coined the term <Term k="rlvr">RLVR</Term>, document theirs.)

**Cutoff and contamination.** Pretraining data is a snapshot, so later facts only arrive through context. Benchmark questions leak into web-scale corpora, so treat headline scores as an upper bound and test on your own tasks.
</Engineer>
