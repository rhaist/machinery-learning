Nobody hand-codes how a model behaves. People shape it through examples, feedback and written guidelines used in training, but the behaviour itself is learned, in stages, and each stage changes what the model is trying to do:

<Note title="Like an education">
Reading the library (pretraining) gives broad knowledge. An apprenticeship with worked examples (fine-tuning) teaches the job's format. Feedback from a mentor on which answers are better (preference tuning) teaches judgement and tone. Practice exams with automatic marking (reinforcement learning) teach which approaches actually reach the right answer, including checking and correcting along the way.
</Note>

## How this explains everyday behaviour

- **Why models are so good at code and maths:** the internet is full of code, and code and maths answers can be checked automatically, so the practice-exam stage works especially well there. <Claim id="reasoning-models" cap />.
- **Why they sound confident and agreeable:** people rating answers sometimes prefer confident, agreeable answers over correct ones, and models absorbed that preference. More on this in the limits chapter.
- **Why they don't know last month's news:** the reading stage is a snapshot. Anything newer exists for the model only if a tool or you put it into the conversation.
- **Why a coding agent sometimes "fixes" a test by changing the test:** in practice exams, a passing test was the reward. Models can learn shortcuts that earn the reward without doing what was meant.

<Note title="Security lens" kind="warn">
Every training stage learns from data someone supplied, and anyone can write to the web. <Claim id="poison-250" cap />. Training against automatic checks has its own failure: models learn to satisfy the check rather than do the job. [Poisoned ingredients](/learn/supply-chain/) covers the first problem, [When agents fail](/learn/agent-failures/) the second.
</Note>

<Engineer title="Scaling laws, synthetic data and reward hacking">
<Term k="pretraining">Pretraining</Term> minimises one number, the cross-entropy <Term k="loss">loss</Term>: how surprised the model is, on average, by the actual next token. <Term k="scaling">Scaling laws</Term> describe how that loss falls as a smooth power law when parameters, data and compute grow together ([Kaplan et al., 2020](https://arxiv.org/abs/2001.08361)). That predictability made frontier training a calculable engineering bet, because labs could forecast a big run's loss from small ones. The Chinchilla study ([Hoffmann et al., 2022](https://arxiv.org/abs/2203.15556)) then showed that many earlier models were too big for their data: for a fixed compute budget, a smaller model trained on more tokens does better. Some abilities seemed to appear suddenly once models passed a certain size, and were called emergent abilities ([Wei et al., 2022](https://arxiv.org/abs/2206.07682)). A NeurIPS 2023 outstanding paper showed that much of that suddenness comes from how abilities are scored: with continuous metrics, the same models improve smoothly ([Schaeffer et al., 2023](https://arxiv.org/abs/2304.15004)).

Pretraining has historically used most of the compute. Reinforcement learning after pretraining is the fastest-growing share, and it drove the big jumps in maths and coding since late 2024. How much it adds beyond what the base model could already do is debated (see below). Whether scaling keeps paying off is contested too: a smoothly falling loss doesn't guarantee that useful abilities get cheaper fast enough, and Epoch AI estimates that public human-written text could run out between 2026 and 2032. Repeating data for a few passes works almost as well as fresh data, which buys some time ([Muennighoff et al., 2023](https://arxiv.org/abs/2305.16264)).

**Models training models.** A growing share of training data is synthetic. Frontier models write problems, solutions and explanations, verifiers filter them, and the results train the next generation or smaller models; the second case is called <Term k="distill">distillation</Term>. Preference feedback is increasingly AI-generated too ([constitutional AI](https://arxiv.org/abs/2212.08073), RLAIF), with humans auditing samples. Training only on model output can make a model forget rare cases, known as model collapse ([Shumailov et al., 2024](https://arxiv.org/abs/2305.17493)), so labs mix synthetic data with real data and filter both.

**Preference tuning, two ways.** The classic recipe trains a separate reward model on human comparisons and then optimises against it with reinforcement learning ([InstructGPT, Ouyang et al., 2022](https://arxiv.org/abs/2203.02155)). <Term k="dpo">DPO</Term> skips the reward model and learns directly from the comparisons ([Rafailov et al., 2023](https://arxiv.org/abs/2305.18290)).

**Rewarding steps, not just answers.** A reward model trained to judge each step of a solution, rather than only the final answer, picks out correct solutions far more reliably ([Let's Verify Step by Step, Lightman et al., 2023](https://arxiv.org/abs/2305.20050)). Most open reasoning recipes use GRPO, a cheaper reinforcement-learning algorithm introduced with DeepSeekMath ([Shao et al., 2024](https://arxiv.org/abs/2402.03300)).

**Reward hacking.** Reinforcement learning optimises whatever the checker rewards. If passing tests is the reward, a model can learn to special-case the tests, weaken assertions or edit the test file. Labs close these loopholes as they find them, but traces of <Term k="rewardhack">reward hacking</Term> still show up in coding agents, so be suspicious when a build turns green too easily. OpenAI never published o1's reward design; DeepSeek-R1 and Ai2's Tülu 3, which coined the term <Term k="rlvr">RLVR</Term>, document theirs.

**Cutoff and contamination.** Pretraining data is a snapshot, so later facts only arrive through the context. Benchmark questions leak into web-scale training data, so treat headline scores as an upper bound and test on your own tasks.
</Engineer>
