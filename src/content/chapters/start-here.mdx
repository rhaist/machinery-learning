A large language model (LLM) is a program that has read an enormous amount of text and learned one skill extremely well: **continuing text**. Give it the beginning of something, and it predicts what comes next, one small piece (a word or part of a word) at a time. ChatGPT, Claude, Gemini and the AI in your coding tools are all built around this one skill.

That sounds like the autocomplete on your phone, and in a sense it is. The difference is scale. Your phone has learned a few common phrases. An LLM has learned from a huge slice of the public internet, plus books, code and scientific papers: far more text than any person could read in many lifetimes. To predict well across all of that, it had to pick up far more than vocabulary: grammar, facts, writing styles, how arguments are structured, how code behaves. Nobody programmed those things in. They emerged because they help with predicting the next word.

Try it. The numbers are made up, but the mechanism is the real one: at every step the model only asks which word is likely to come next.

## How it was built, in three stages

1. **Reading.** The model reads trillions of words, and for each one it practises guessing the next word, then nudges itself to guess better. This is where its knowledge comes from. At the end it is a superb autocomplete, but not yet an assistant: ask it a question and it might just write more questions.
2. **Apprenticeship.** It is shown many examples of helpful conversations, and taught which answers people prefer. Now it answers like an assistant.
3. **Practice with feedback.** It practises tasks with automatic checking, such as maths with known answers or code with tests, and is rewarded when it gets them right. This made models far better at long, careful problem solving and at using tools reliably, which is why today's AI can run tests and fix the bug it finds.

These three stages are also, roughly, the order in which the field worked things out. The optional page [How we got here](/learn/how-we-got-here/) tells that story in five minutes.

## What it is not

- **Not a database.** It doesn't look facts up. It reconstructs them from patterns it learned, which is why it can be confidently wrong. Tools like web search help, when they're connected.
- **Not learning from you during the chat.** Once trained, the model is frozen and doesn't change while you talk to it. It "remembers" a conversation only because the whole conversation is fed back in each time. Memory features in apps work the same way: saved notes get added to what the model reads. Whether your chats are used to train *later* versions is a separate question that depends on the provider and your settings; [Where your words go](/learn/your-data/) explains it.
- **Not a person,** even though it writes like one. It has absorbed how people talk about feelings and intentions; that doesn't settle whether it has any.

<Engineer title="The same story in engineering terms">
Under the hood, an LLM is a <Term k="transformer">transformer</Term>: a stack of identical blocks that each refine a list of numbers for every piece of text.

The path from input to output is short. Your text is split into <Term k="token">tokens</Term>, and each token becomes a vector, a long list of numbers. The vectors pass through the stack. Each block has two parts: <Term k="attention">attention</Term> lets a token pull in information from earlier tokens, and an <Term k="mlp">MLP</Term> then works on each token by itself. At the end, the model gives a probability for every token in its vocabulary, and one is picked.

<ForwardPass />

Two things stand out. The data keeps the same shape all the way through the stack, one row of 8,192 numbers per token, because every block adds its result to the rows instead of replacing them. And most of the parameters sit in the MLPs, which work on one token at a time. That is part of why researchers look there for stored facts.

The three training stages above have technical names. Reading is <Term k="pretraining">pretraining</Term>: predicting the next token across tens of trillions of tokens. Apprenticeship is supervised fine-tuning (<Term k="sft">SFT</Term>) on example conversations, followed by preference tuning (<Term k="rlhf">RLHF</Term> or <Term k="dpo">DPO</Term>). Practice with feedback is reinforcement learning with verifiable rewards (<Term k="rlvr">RLVR</Term>).

When it answers, the model writes one token at a time, which is called <Term k="autoregressive">autoregressive</Term> generation. It keeps the intermediate results for earlier tokens in a <Term k="kv">KV cache</Term> so it doesn't recompute them. Coding agents wrap the model in a <Term k="harness">harness</Term>, ordinary software that runs the tools the model asks for.

All of this rests on two memories with nothing in between: the frozen weights hold what the model learned in training, and the <Term k="context">context window</Term> holds the current conversation.
</Engineer>
