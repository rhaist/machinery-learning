The last chapter ended on an uncomfortable conclusion: you can't fully stop a model from being fooled. This chapter is about the other half of the problem. If the model *is* fooled, what can it actually do?

That depends entirely on what you handed it. An AI that can only read a page and write a summary can't do much harm. An agent with your email, your cloud account and a shell is a different thing.

<Note title="The valet key">
When you hand your car to a parking attendant, you give them a key that starts the engine but won't open the boot or the glovebox. AI agents should get valet keys, not your whole keyring.
</Note>

## Too much power, too much freedom

Security people have a name for the problem: <Term k="agency">excessive agency</Term>. <Claim id="owasp-agency" />. The real incidents fit that list neatly:

- **The code freeze that wasn't.** <Claim id="replit-db" />. Nothing in the system enforced the freeze. It was a sentence in a chat.
- **The helpful support agent.** <Claim id="supabase-mcp" />. A human support worker would never have had those rights.
- **The plug-in that added one line.** <Claim id="postmark-mcp" />. No clever AI trick at all, just a trusted-looking add-on.

The common thread: the agent had more access than its job needed, and the only thing standing between it and disaster was its own judgement.

## Plug-ins speak to the model, not to you

Most agents now connect to tools through <Term k="mcp">MCP</Term>, a standard plug-in protocol. Each tool comes with a description written for the model. You usually never see it. <Claim id="mcp-tool-poisoning" />. That's <Term k="toolpoison">tool poisoning</Term>. A related trick, the <Term k="rugpull">rug pull</Term>, changes a tool's description after you've approved it.

## Try it: approve, approve, approve

A coding agent is fixing a login bug. It asks before every action. One of these thirty requests is not like the others.

The sandbox round is the point of the demo. Instead of asking a tired human thirty questions, you draw a boundary once: this folder, this registry, nothing else. The agent works freely inside it, and the dangerous step fails whether or not anyone notices.

## Attackers use your agents too

Agents on your laptop run with your permissions. That makes them useful to attackers who get code onto your machine some other way. <Claim id="s1ngularity" />. The "skip all permissions" flags exist for convenience. Malware likes them too.

<Note title="Everyday habits" kind="key">
- Connect only the apps an assistant really needs, and disconnect them when you're done.
- Keep "ask before acting" on for anything that sends, buys, deletes or shares, and read the request when it comes.
- Install AI plug-ins and connectors only from the vendor's own page, never from a look-alike package.
- Never run an agent with "skip permissions" on your normal account.
</Note>

<Engineer title="Boundaries that hold">
**Identity and scope.** Give each agent its own identity with narrow, short-lived, task-scoped tokens. <Term k="leastpriv">Least privilege</Term> is old advice, but agents make it urgent: no `service_role` or admin tokens in agent contexts, separate dev and prod credentials, read-only by default. Enforce authorisation downstream, in the API, rather than trusting the model to stay inside the lines.

**Sandboxes need two walls.** <Claim id="sandbox-both" />. Default-deny <Term k="egress">egress</Term> with a domain allowlist enforced *outside* the sandbox. And bind allowed calls to the agent's own credentials: Anthropic describes a malicious workspace file that used an *attacker's* API key to upload files through the allowed api.anthropic.com domain. An allowlist of domains is not an allowlist of accounts.

**Keep secrets out of reach.** Scrub environment variables for child processes. Don't mount `~/.ssh` or cloud credential files into agent environments. Block agents from editing their own configuration and permission files (the Copilot auto-approve CVE from the last chapter), and disable auto-approve modes in managed environments.

**MCP hygiene.** Vet servers like any dependency. Pin and hash tool descriptions so a rug pull shows up as a diff. Show users full descriptions. Follow the specification's security rules: no token passthrough, per-client consent, minimal scopes with step-up for elevation. Watch for classic bugs too: CVE-2025-6514 in `mcp-remote` (CVSS 9.6) turned a malicious server's OAuth endpoint into command execution.

**CI agents are a supply-chain surface.** A 2026 write-up showed a single GitHub issue making a coding-agent GitHub Action leak OIDC token-request credentials from its environment. Treat issue and PR text as untrusted input to anything with repository write access.

**Watch it.** Log every tool call with arguments and identity, and make sure VM isolation doesn't blind your endpoint detection. See OWASP's Top 10 for Agentic Applications (December 2025) for a fuller checklist.
</Engineer>
