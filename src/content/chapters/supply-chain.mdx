The previous chapters covered attacks that reach the model while it's working. Other attacks happen earlier, in the ingredients: the code the AI told you to install, the model file you downloaded, the text the model was trained on, or the AI tool itself.

<Note title="The recipe book that invents brand names">
A recipe book sometimes names ingredients that don't exist: "use FreshCo baking powder". A con artist reads the book, opens a shop called FreshCo, and sells something nasty. Nobody hacked the book. The attacker just waited where its readers would go.
</Note>

## Packages that never existed

Ask a chatbot how to set something up and it will often give you an install command. Sometimes the package it names doesn't exist. <Claim id="pkg-hallucination" cap />. On its own that's an annoyance: the install fails and you move on.

It becomes an attack because the inventions are predictable. <Claim id="pkg-repeat" cap />. If a model keeps suggesting the same fake name, someone can register it and wait. This is called <Term k="slopsquat">slopsquatting</Term>, a cousin of <Term k="typosquat">typosquatting</Term>. The early proof was harmless: <Claim id="huggingface-cli" />. Now the invented commands are spreading through the instruction files that coding agents read, where an agent may run them without a human ever seeing the line.

## Model files that run code

A downloaded AI model sounds like data: a big file of numbers. Often it isn't. The most common format in the PyTorch world, <Term k="pickle">pickle</Term>, can carry instructions that run the moment you load it. <Claim id="pickle-malicious" cap />.

Platforms scan for this, but scanners look for known-bad patterns, and attackers test against them. <Claim id="nullifai" cap />. Even PyTorch's "safe" loading mode had a hole until version 2.6. The real fix is a format with nothing to execute: <Term k="safetensors">safetensors</Term> stores only numbers and a header.

<Note title="Flat-pack furniture" kind="key">
A pickle file is flat-pack furniture that assembles itself when you open the box, including any extra instructions someone slipped in. Safetensors is a box of plain parts. Downloaded models are software: treat them like an `.exe` from a stranger.
</Note>

## Poisoning the well

The deepest ingredient is the training data. Models learn from huge scrapes of the web, and anyone can write to the web. <Term k="poisoning">Data poisoning</Term> plants text designed to teach a model something its makers didn't intend, such as a hidden trigger that changes its behaviour, a <Term k="backdoor">backdoor</Term>.

Earlier work measured poisoning as a share of the training data, but the absolute number of documents turned out to matter: <Claim id="poison-250" />, a trigger that made the model produce gibberish. And getting text into a dataset is cheap: <Claim id="poison-cheap" />. Worse, once a backdoor is in, it can be hard to get out. <Claim id="sleeper-agents" cap />.

## The tools themselves

Finally, AI tools are software with their own supply chains, and attackers have noticed. <Claim id="litellm" cap />. An AI gateway like that holds the keys to every model a company uses, and often cloud credentials too.

<Note title="Everyday habits" kind="key">
- Never paste an install command from a chatbot without checking that the package is real, established and the one the official docs name.
- Install AI browser extensions and editor plug-ins only from the vendor's own listing, and remove the ones you don't use.
- Treat downloaded models like programs from a stranger, not like documents.
</Note>

<Engineer title="Hardening the AI supply chain">
**Packages.** Route installs, including agent installs, through a proxy or allowlist that blocks brand-new and low-reputation packages. Review agent "skills" and rules files like code: they're instructions an agent will follow. Pin and hash dependencies, and prefer trusted publishing (OIDC) over long-lived registry tokens. The Amazon Q extension incident (July 2025, CVE-2025-8217) started with an over-broad GitHub token in build configuration; the Nx compromise from the last chapter started with a CI workflow.

**Models.** Standardise on non-executable formats. Patch PyTorch to 2.6 or later (CVE-2025-32434 broke `weights_only=True`). Load unknown models only in isolated, network-less sandboxes. Prefer known publishers, but remember a publisher account can be taken over.

**Provenance.** <Claim id="model-signing" cap />. Sign the models you produce, verify signatures on intake, and keep provenance records for datasets. Be clear about what a <Term k="signing">signature</Term> gives you: proof of *who* published a file and that it wasn't altered afterwards. It says nothing about whether the training data was clean.

**Poisoning defence** is mostly upstream: data curation, deduplication, monitoring sources that change hands (expired domains), and post-training evaluations that look for trigger behaviour. If you fine-tune on scraped or user-submitted data, you inherit this problem directly.

**Crown jewels.** Treat AI gateways and AI command-line tools as high-value software. They aggregate API keys and often run with broad local permissions. Rotate credentials fast when an incident like LiteLLM's lands; note that its two published accounts disagree on the entry point, which is common in the first weeks of an incident.
</Engineer>
